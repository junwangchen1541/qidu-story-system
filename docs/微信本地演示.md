# 微信本地演示

当前实现是原生微信小程序（`compileType: miniprogram`，WXML/WXSS 页面）。小游戏使用独立的入口和渲染层，未来可在同一仓库中复用 `packages/story-core` 与路线数据。

## 生成章节

在仓库根目录执行；将占位参数换成本机路径和自己的测试号：

```powershell
npm run build:private -- '<私有素材库根目录>'
node tools/verify-private.js '<私有素材库根目录>'
node tools/prepare-wechat-local.js '<AppID>' build_private/apps/wechat '<本机演示目录>'
```

演示目录首次应为空。再次生成时，脚本通过 `.qidu-local-build.json` 确认目录属于同一来源和路线；保留开发者工具的 `project.private.config.json`。修改源码后重新生成演示副本，不直接在副本中开发。

`apps/wechat/` 是公开占位版；完整章节生成到 ignored `build_private/`，再复制到本机演示目录。遇到 G 盘 `UNKNOWN: read` 时，可选择 C 盘目录。

## 人工验证

1. 开发者工具导入生成的演示目录，类型选小程序，使用自己的测试号，不使用云服务。
2. 编译后核对标题与目标章节一致，确认地图、顶部三个按钮完整显示。
3. 进入起点，确认黑屏文字和“继续”按钮可见；继续到对白，检查背景、人物和文字。
4. 选择工具的“预览”，用当前测试号所属微信扫码；遇到报错时记录完整信息并检查账号权限与包体。
5. 手机上检查长文本滚动、按钮点击、私信解锁，以及退出后重新进入的存档恢复；结果单独登记为真机验收记录。

只需记录手机型号、微信版本、出现问题的事件/文字位置、操作步骤与报错；画面问题补充一张截图即可。
