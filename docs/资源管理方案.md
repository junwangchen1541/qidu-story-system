# 游戏资产与构建管理

## 项目目录

代码仓库维护游戏程序、剧情数据结构、工具、资源清单和版本文档。公开演示通过通用占位资源展示系统流程。

本地资产库维护制作素材、校对材料和开发构建。构建工具依据资产清单及目标平台生成对应内容包。

## 目录约定

```text
qidu-story-system/
  apps/
  data/routes/
  docs/
  schema/
  tools/
  manifest/
  build_private/

qidu-game-assets/
  apk/
  extracted_text/
  cg/
  portrait/
  audio/
  ocr/
  build_private/
```

开发素材与账号配置按本机目录和 IDE 私有配置管理；构建目录保持可再生成，正式版本使用独立归档。

## manifest 管理

当前 CSV 模板记录资产路径、占位资源、来源、状态和校验值：

```csv
id,type,title,private_path,public_placeholder,status,source_note,sha256
bg_awake,bg,醒来,private/cg/001.jpg,demo_public/placeholders/bg_awake,private_only,本地私有资源,
```

`sha256` 用于校验素材版本。发行审核补充授权状态、署名和平台范围，按 [素材与发布管理](版权与公开边界.md) 人工核对；当前构建脚本按路线和资源映射生成开发包，授权与发行状态检查列入后续工具开发。

## 构建原则

- `demo_public` 提供可独立运行的系统演示。
- `apps/web` 与 `apps/wechat` 只负责平台渲染，共享 `packages/story-core` 和 `data/routes`。
- 路线条件、变量效果、私信读取、存档序列化等行为只在 `packages/story-core` 维护，平台端不复制状态机。
- 每个平台维护独立的构建配置、包体检查和验收记录。
- 开发构建、发行构建和版本归档分别管理；发行构建记录提交、平台、资产清单版本与校验值。
